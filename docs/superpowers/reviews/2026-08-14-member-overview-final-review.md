## P1

### 已修复：管理员仍能绕过页面直接录入或修改业务数据

- 证据：正式规格明确“管理员不录业务数据”，但修复前管理员调用 `POST /api/batches`、`POST /api/events` 会得到 `201`，访问 `/entry` 也不会跳走；管理员还可以 PATCH 自己以前的历史业务记录。
- 风险：管理员身份本来只负责治理和分析，却能制造业务数据，审计归属会混乱。
- 修复：批次、事件和历史修改三个服务端入口都拒绝管理员；管理员访问 `/entry` 重定向到 `/dashboard`，侧边栏不再显示“数据录入”。
- 回归证据：`tests/e2e/role-workflow.spec.ts` 同时验证 API、页面跳转、导航和伪造 `enteredById`；`tests/unit/history-update.test.ts` 与 `tests/unit/navigation.test.ts` 验证历史修改和导航边界。

## P2（记录后交用户复审，不在本阶段继续抛光）

### 1. “连续改善天数”没有可计算的服务端合同

- 当前列表只有相对上一等长周期的趋势，每日证据只提供连续偏低天数；没有逐日“改善成立”的定义或字段。
- UI 保持显示 `—`，没有猜数字。
- 若以后必须展示真实天数，需要产品先定义“改善”的日级口径，再扩展查询合同。直接拿周期趋势硬凑天数会误导管理判断。

### 2. 手机端侧边导航占用首屏较多

- 390×844 真实浏览器检查中，导航在页面顶部占约 320px，用户需要向下滚动才能更快看到筛选和数据卡片。
- 组员总览已经正确切换为卡片，详情也正确全屏，因此不阻塞核心使用；这是下一轮 UI 精简项，不在本次角色/财务/风险功能里扩修。

### 3. 开发和测试工具仍有非阻塞警告

- Prisma 提示 `package.json#prisma` 将在 Prisma 7 弃用。
- Next.js 提示 worktree 下存在多个 lockfile，并提示未来版本需要设置 `allowedDevOrigins`。
- E2E 正常结束会清理临时工作区，但进程异常中止时曾残留大体积临时目录；本次仅清理了明确命名的 E2E 临时目录，没有删除项目数据。
- 这些警告不影响当前 build 或运行，可在独立基础设施任务中处理。

### 4. 极窄的“写入过程中角色刚好变更”竞态

- 批次和事件 API 在请求入口已经拒绝 ADMIN，但事务内部重新读取当前账号后，没有再次明确限制为 LEAD/MEMBER。
- 只有账号在一次写请求已经通过入口检查后、事务重读前，恰好被另一个管理员提升为 ADMIN，才可能多完成这一次写入；普通管理员请求和稳定角色均已被 403/归属测试覆盖。
- 现实窗口很窄，且角色变更本身需要管理员权限，因此本轮按 P2 记录。后续可把事务内重新读取的 actor 也明确收窄为 LEAD/MEMBER，彻底消除这类竞态。

## 计算与状态审查

- 财务公式保持为：消耗 = 有效粉 × 渠道固定价；净业绩 = 充值 + 通道业绩 − 出金；纯利 = 净业绩 − 消耗。
- 待定价渠道不会生成假消耗或假纯利。
- 渠道校正效率使用同组同渠道其他人员为基准并排除本人。
- 退群率按低到高，其余转化指标按高到低；分母为 0 显示 `—`。
- 表现、财务和数据风险分区展示；培训/观察保护与数据阻断规则通过单元测试。
- 未定价、观察中、样本不足、无数据和加载失败有不同组件状态；真实浏览器确认了无数据/样本不足，自动化测试覆盖待定价和观察中，代码检查确认加载失败使用独立错误边界与“重新加载”操作。
