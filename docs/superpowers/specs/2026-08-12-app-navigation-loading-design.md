# 全站页面切换骨架屏设计

## 目标

解决侧边栏切换页面时短暂无反馈、让用户误以为点击无效的问题。点击任意侧边栏入口后，侧边栏与顶部栏保持不动，内容区立即显示轻量骨架屏，待服务端页面和数据返回后自动展示真实内容。

## 已确认方案

采用 Next.js App Router 的公共路由加载界面，在 `src/app/(app)` 路由组中增加统一 `loading.tsx`。不让侧边栏自行维护加载状态，也不为每个页面重复制作一套骨架。

这样所有登录后的页面都自动获得一致反馈，包括管理概览、数据录入、历史记录、团队表现、渠道分析、异常榜单、批次追踪和人员管理页面。

## 界面行为

- 点击侧边栏链接后，侧边栏和顶部栏继续显示，不闪烁、不重建。
- 内容区显示与现有后台风格一致的浅灰色骨架：标题、筛选区域、四个指标卡片和表格行。
- 骨架只表达“页面正在加载”，不显示虚假数字、文字或业务状态。
- 数据加载完成后，由真实页面整体替换骨架。
- 连续点击仍交给 Next.js 路由处理，不新增遮罩、锁屏或自定义计时器。
- 用户启用“减少动态效果”时停止骨架动画。

## 技术边界

- 保留现有 `AppSidebar`、`AppHeader` 和公共 `AppLayout`。
- 不修改数据库查询、统计口径、权限、登录状态或路由地址。
- 不引入新的依赖。
- 使用现有 CSS 颜色和圆角规范；动画仅使用透明度变化，避免页面抖动。

## 异常处理

页面报错仍由各页面现有 `error.tsx` 处理；骨架屏不吞掉错误，也不设置超时提示。开发模式首次编译仍可能耗时数秒，但点击后会立即获得明确反馈。正式构建不会发生开发模式的首次按页编译。

## 验证标准

1. 公共加载组件能被独立渲染，并包含可访问的“正在加载页面”状态。
2. 所有登录后侧边栏页面共享同一骨架屏，登录页不受影响。
3. 浏览器点击团队表现、渠道分析、异常榜单和批次追踪时，公共框架保持可见。
4. 加载完成后页面内容和原有导航权限不变。
5. 聚焦测试、完整单元测试和生产构建通过。
