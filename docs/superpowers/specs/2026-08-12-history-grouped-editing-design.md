# 历史记录分组与本人编辑设计

## 目标

把当前“一项指标占一行”的历史记录改成“同一次业务记录占一行”。用户能快速看懂某天、某个粉来源批次填写了哪些数据，并能纠正自己录错的内容。

本次只改历史记录的查看与本人编辑流程，不改变报表公式、来源批次定义或现有录入页。

## 核心分组规则

一组历史数据由以下三项共同确定：

- 录入人；
- 发生日期；
- 粉来源批次，即“来源日期 + 渠道 + 小组”。

同一组内的获粉、回复、入群、退群、专家介绍、注册、下单和充值合并展示。数据库仍保留指标事件，页面只是把它们汇总成一组，避免重复日期和渠道占满整张表。

如果同一指标曾被分多次录入，历史页显示这些事件的合计值；编辑时修改的是这一组该指标的最终合计值。

## 历史记录页面

### 页面顶部

- 标题仍为“历史记录”。
- 补充说明：“按发生日期和粉来源批次汇总；你可以修改自己录入的数据。”
- 显示“共 N 组”，不再显示“共 N 条”，避免把指标数量误认为填写次数。

### 筛选区

- 发生日期；
- 来源日期；
- 渠道与小组；
- 录入人：只对组长和管理员显示，普通成员不显示无意义的成员筛选；
- “清除筛选”只在存在筛选条件时显示。

### 日期分组列表

记录先按发生日期分区，最近日期在前。每个分区标题显示日期与当天记录组数。

每组记录使用一行紧凑卡片：

1. 左侧显示来源日期、渠道、小组和录入人；
2. 中间按业务顺序显示非零指标：获粉、回复、入群、退群、专家、注册、下单、充值；
3. 零值默认不占空间，展开详情后仍可查看全部指标；
4. 停用渠道或停用成员保留原名称并显示“已停用”；
5. 自己录入的记录显示“编辑”，其他人的记录只显示“查看详情”。

整行可展开查看完整八项指标，但只有“编辑”按钮会进入修改状态，避免误点。

## 编辑抽屉

点击“编辑”后，从右侧打开抽屉，页面列表保持原筛选和滚动位置。

### 基本信息

- 发生日期：可修改；
- 粉来源批次：可重新选择，选项显示“来源日期 · 渠道 · 小组”；
- 原录入人：只读；
- 原来源批次已停用时允许继续修改数值，但若要更换来源，目标批次必须处于启用状态且当前用户有写入权限。

若目标的“发生日期 + 粉来源批次”已经存在该用户的另一组记录，系统不自动合并，而是提示用户先打开已有记录修改，防止两组数据被意外相加。

### 指标区

按录入页的顺序分为三段：

- 获粉与回复；
- 入群与退群；
- 转化与充值：专家介绍、注册、下单、充值金额。

数量只能填写 0 或正整数；充值金额只能填写 0 或正数。空白按 0 处理。保存失败时保留所有输入。

### 保存确认

保存前显示有变化的字段，例如：

- 回复：20 → 18；
- 入群：10 → 8；
- 发生日期：2026-08-12 → 2026-08-11。

没有变化时不允许保存。保存成功后关闭抽屉、刷新当前分组，并显示成功提示。

## 权限

- 每个登录人只能编辑自己录入的数据，包括普通成员、组长和管理员自己的记录；
- 普通成员仍只能查看自己的数据；
- 组长可以查看本组记录，但不能替组员修改；
- 管理员可以查看全部记录，但不能直接修改别人录入的数据；
- 所有编辑请求都必须在服务端重新检查当前账号、原记录归属、目标来源批次和小组范围，不能只依赖页面隐藏按钮；
- 停用账号不能编辑。

## 数据更新规则

保存采用一个数据库事务：要么整组八项指标全部修改成功，要么完全不修改。

对每个指标：

- 新合计大于 0 且原来没有事件时，新建一个事件；
- 原来已有一条或多条事件时，第一条保存新合计，其余旧事件归零而不直接删除；
- 新合计为 0 时，原事件归零；
- 充值使用分为单位保存，页面仍按元输入和显示。

这样报表只计算新合计，同时旧事件不会被物理删除，便于追溯。

## 审计记录

每次成功编辑记录一条 `HISTORY_GROUP_UPDATED` 审计日志，包含：

- 操作人；
- 原发生日期和新发生日期；
- 原来源批次和新来源批次；
- 每个变化指标的旧合计和新合计。

日志不包含密码或其他敏感内容。管理员在现有操作日志中可以查看这类修改。

## 错误处理

- 记录不存在、不是本人录入或已经越权时，统一提示“无权修改该记录”；
- 目标来源批次不存在、已停用或跨越可写小组时，提示重新选择来源；
- 目标组合已经存在时，明确提示打开那组记录修改；
- 两个页面同时编辑同一组时，页面提交打开抽屉时取得的版本指纹；服务端在事务中按事件编号和值重新计算指纹，发现内容已经变化就返回“这组数据已被更新，请刷新后再修改”，避免旧页面覆盖新数据；
- 网络或服务端失败时，抽屉不关闭，保留输入并允许重试。

## 验收标准

- 当前截图中的 7 条指标应合并显示为 1 组；
- 页面显示“共 1 组”，普通成员不再看到“成员”筛选；
- 成员可以展开完整指标并打开编辑抽屉；
- 修改数字、发生日期或来源批次后，历史页和报表同步使用新数据；
- 成员不能编辑别人数据，组长和管理员也不能替别人修改；
- 停用渠道和离职成员的历史名称仍然保留；
- 修改内容可在管理员操作日志中追溯；
- 桌面端保持当前侧边栏和视觉风格，窄屏不会出现不可操作的横向大表。

## 本次不做

- 彻底删除历史记录；
- 组长或管理员代替成员修改；
- 批量修改多组记录；
- 恢复到任意旧版本；
- 改变报表公式或转化率定义。
