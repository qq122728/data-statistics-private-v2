# 管理员与组长数据分析四入口设计

日期：2026-08-12  
状态：已实现

## 1. 目标

把当前集中在“工作台”和“转化报表”的人员、渠道、批次、漏斗信息拆开，让管理员和组长按管理问题进入对应页面，而不是在一个超长页面里自己找数字。

这次设计只服务四个问题：

1. 今天最需要先处理什么？
2. 哪个小组、哪个业务人员表现好或需要辅导？
3. 哪个渠道带来的粉更有质量？
4. 哪个来源批次现在需要继续跟进？

## 2. 已确认的业务口径

- 谁录入数据，业绩就归谁。
- 组长只录入自己的业务数据，不代替组员录入。
- “业务人员”包含组长和普通组员。
- 管理员可以查看全部小组；组长只能查看本组；普通成员不开放新增的管理分析入口。
- 现有报表公式保持不变。
- 增量模式下的“群内”改名为“本期净增在群”，避免误解成当前真实群人数。
- 停用或离职人员的历史数据继续参与其原有历史范围统计，并允许通过“包含历史人员”筛选追溯。

## 3. 侧边栏信息架构

侧边栏按任务分组：

```text
日常工作
  管理概览
  数据录入
  历史记录

数据分析
  团队表现
  渠道分析
  批次追踪

人员管理
  管理员中心 / 组员管理
```

角色差异：

| 入口 | 管理员 | 组长 | 普通成员 |
| --- | --- | --- | --- |
| 管理概览 | 全部小组或指定小组 | 自动限定本组 | 保留现有个人工作台，不显示管理提醒 |
| 团队表现 | 小组对比并下钻全部业务人员 | 本组业务人员 | 不显示 |
| 渠道分析 | 全部小组与渠道 | 本组渠道数据 | 不显示 |
| 批次追踪 | 全部小组批次 | 本组批次 | 不显示 |
| 人员管理 | 管理员中心 | 组员管理 | 不显示 |

普通成员现有“数据录入、历史记录、个人转化报表”保留，不强行改成管理型页面。

## 4. 共用交互规则

- 每个分析页面只回答一个主问题，不重复放同一张完整表。
- 页面顶部只显示 2–3 个常用筛选，其余放进“更多筛选”。
- 管理员常用筛选：日期、小组；组长不显示小组筛选。
- 切换页面或下钻时保留日期、小组、成员、渠道条件。
- 表格主视图只保留作出判断所需的 5–7 列；人员与渠道的完整指标进入右侧详情抽屉，内容更长的批次进入二级详情页。
- 所有转化率旁必须显示获粉样本量；样本不足不得进入正式排名。
- 第一版最低样本量为 20 个粉，显示“样本不足”，不做红绿优劣判断。
- 默认时间按页面任务设置，不使用一个全局默认范围强套所有页面。
- 空状态要说明“没有数据”“筛选后没有数据”或“数据尚未成熟”，不能都显示为 0。

## 5. 管理概览

### 唯一问题

今天最需要先处理什么？

### 默认范围

- 业务结果：最近 7 天发生数据。
- 数据待处理：今天。
- 管理员：全部小组。
- 组长：固定本组。

### 页面顺序

1. 日期与小组范围。
2. 数据待处理摘要。
3. 四个核心结果：获粉、开单、充值、开单率。
4. 最近 7 天开单与充值趋势。
5. 最大漏斗掉点摘要。
6. 异常对象快捷入口。

### 数据待处理

第一版包含：

- 今日未确认数据的业务人员。
- 连续 3 个自然日没有记录。
- 有回复但没有对应获粉。
- 同一来源批次内，注册大于专家介绍、专家介绍大于入群、开单大于获粉等确定违反现有漏斗口径的情况。
- 退群大于累计入群。

点击提醒后跳到已带筛选的“团队表现”“渠道分析”或“批次追踪”。

### 今日数据已确认

- 每位业务人员每天可以确认一次“今日数据已填写完成”。
- 当天全部为 0 也要确认，系统才能区分“没有业务”和“忘记填写”。
- 新增确认记录保存业务人员、业务日期、确认时间。
- 如果确认后又录入或修改当天数据，确认仍有效，但更新时间用于审计。
- 管理员和组长只能查看确认状态，不能代替他人确认。

### 不允许放入

- 完整业务人员排名。
- 完整渠道表。
- 来源批次明细长表。
- 完整九阶段漏斗。
- 账号、密码、启停等管理操作。

## 6. 团队表现

### 唯一问题

哪个小组、哪个业务人员表现好，谁需要辅导？

### 默认范围与排序

- 默认来源日期最近 30 天，累计到今天。
- 管理员默认先看小组表现；组长直接看本组业务人员。
- 默认按充值降序；充值相同时按开单数、获粉数排序。
- 转化率排名默认优先使用已达到 D7 的成熟批次，避免新粉拖低结果。
- 不做“综合得分”，避免不透明权重误导管理者。

### 管理员小组表现

列项：

- 小组。
- 活跃业务人员数。
- 获粉。
- 开单。
- 充值。
- 人均开单。
- 开单率。

点击小组后进入该小组的业务人员列表，保留当前时间范围。

### 业务人员表现

主表列项：

- 姓名与角色。
- 获粉样本量。
- 入群率。
- 注册率。
- 开单率。
- 开单数。
- 充值。

支持按每个数值列排序。停用人员在启用“包含历史人员”时出现，并标明“已停用”。

点击人员打开右侧详情抽屉：

1. 个人核心结果。
2. 完整漏斗与最大掉点。
3. 最近趋势。
4. 来源渠道构成。
5. “查看相关批次”跳到批次追踪。

### 不允许放入

- 渠道总体排名。
- 来源批次长表。
- 账号启停和密码重置。
- 全部九项数量卡。

## 7. 渠道分析

### 唯一问题

哪个渠道带来的粉更有质量？

### 默认范围与排序

- 默认来源日期最近 30 天，累计到今天。
- 默认按“充值/粉”降序，其次按开单率。
- 获粉少于 20 的渠道放入“样本不足”，不参与正式排名。

### 渠道质量主表

只展示：

- 渠道。
- 获粉样本量。
- 入群率。
- 注册率。
- 开单率。
- 充值/粉。

点击渠道打开详情抽屉：

- 回复率。
- 退群率。
- 专家介绍率。
- 充值/开单。
- 完整渠道漏斗与最大掉点。
- D7、D14 累计转化。
- 涉及的小组。
- “查看相关批次”跳到批次追踪。

### 不允许放入

- 业务人员排名。
- 今日未确认提醒。
- 全部来源批次直接铺开。
- ROI、获客成本和利润，因为系统还没有渠道费用数据。

## 8. 批次追踪

### 唯一问题

哪一批粉现在需要继续跟进？

### 默认范围与优先级

- 默认来源日期最近 14 天。
- 未完成转化的批次排在前面。
- 同为未完成时，年龄较大的批次优先。
- 已开单或无待跟进信号的批次放后面。

### 批次年龄

- D0：来源当天。
- D1–3：来源后 1–3 天。
- D4–7：来源后 4–7 天。
- D8–14：来源后 8–14 天。
- D15+：来源后 15 天及以上。

### 批次主列表

展示：

- 来源日期。
- 渠道。
- 业务人员。
- 小组（组长不显示）。
- 批次年龄。
- 获粉量。
- 当前阶段。
- 最大卡点。
- 开单数。
- 跟进状态。

“当前阶段”使用已经产生非零结果的最深漏斗阶段。第一版“跟进状态”只做规则状态，不做人工任务流：

- 正常转化。
- 转化停滞：批次获粉不少于 20、批次年龄达到 D4、尚未开单，且连续 3 个自然日没有产生比当前阶段更深的新转化。
- 样本不足。
- 已产生开单。
- 数据异常。

### 批次详情

点击批次进入二级详情页：

1. 来源日期、渠道、人员、小组和年龄。
2. 完整转化漏斗。
3. 最大掉点与损失人数。
4. D7、D14 累计转化。
5. 各阶段发生日期趋势。
6. 对应历史录入记录。

### 不允许放入

- 小组和人员总排名。
- 渠道总体排名。
- 全团队长期趋势。
- 账号管理操作。

## 9. 漏斗能力如何分布

不建立独立“转化诊断”一级入口。漏斗是检查工具，跟随管理对象出现：

- 管理概览：只显示当前最大掉点摘要，点击打开全局漏斗抽屉。
- 团队表现：人员详情显示该人员漏斗。
- 渠道分析：渠道详情显示该渠道漏斗。
- 批次追踪：批次详情显示最完整漏斗。

这能保留诊断能力，又避免新的“转化诊断”页面再次堆满小组、人员、渠道、日期和批次筛选。

## 10. 页面下钻关系

```text
管理概览
├─ 未确认人员 → 团队表现（保留日期和人员条件）
├─ 异常渠道 → 渠道分析（保留渠道条件）
├─ 转化停滞批次 → 批次追踪（保留批次条件）
└─ 最大掉点 → 全局漏斗抽屉

团队表现
├─ 小组 → 本组业务人员
└─ 业务人员 → 人员详情抽屉 → 相关批次

渠道分析
└─ 渠道 → 渠道详情抽屉 → 相关批次

批次追踪
└─ 批次 → 批次详情 → 历史记录
```

## 11. 现有页面迁移

- “工作台”对管理员和组长改成“管理概览”并大幅瘦身。
- 普通成员保留现有个人工作台。
- “数据录入”保留。
- “历史记录”保留。
- 管理员/组长现有“转化报表”拆分：
  - 渠道对比迁到“渠道分析”。
  - 来源批次表迁到“批次追踪”。
  - 漏斗迁到对应对象详情。
- 普通成员继续保留个人转化报表。
- “管理员中心”和“组员管理”保留，账号管理与只读业务分析不混合。

## 12. 数据与错误状态

- 页面查询失败时保留筛选条件，并提供“重新加载”。
- 页面之间下钻的筛选参数必须验证权限；组长手工修改 URL 也不能访问其他小组。
- 今日确认提交必须防止重复记录，重复点击返回已有确认结果。
- 分母为 0 时显示“暂无数据”，不能显示 0%。
- 样本未达到 20 时显示具体样本量和“样本不足”。
- D7/D14 尚未成熟时显示“尚未达到 D7/D14”，不能用当前结果冒充成熟结果。
- 停用人员、渠道和小组保留历史名称与停用标识。

## 13. 第一版范围

第一版实现：

1. 管理概览瘦身和数据待处理。
2. 今日数据已确认。
3. 团队表现的小组/业务人员表与详情抽屉。
4. 渠道质量主表与详情抽屉。
5. 批次年龄、批次优先级列表和批次详情。
6. 漏斗按对象分布和筛选条件跨页保留。

第一版不实现：

- 目标管理。
- 渠道费用、ROI 和利润。
- AI 预测或自动推荐。
- 单粉真实转化周期、复充率和重复注册。
- TG/邮件消息推送。
- 人工分配的跟进任务工作流。
- 可配置综合评分。

## 14. 验收标准

### 信息密度

- 每个入口只存在一个主分析对象。
- 管理概览不出现完整人员、渠道或批次长表。
- 主表在常用桌面宽度内无横向滚动；完整数据通过详情查看。

### 权限

- 管理员可以查看全部小组并下钻。
- 组长所有查询和下钻都固定在本组。
- 普通成员不能进入新增管理分析页面或接口。

### 数据口径

- 业务人员数据按录入人归属。
- 排名显示样本量，少于 20 不参与正式排名。
- 新老批次通过年龄和 D7/D14 成熟度区分。
- 分母为 0 和尚未成熟有不同提示。

### 核心流程

- 管理概览提醒能跳到带好筛选的目标页面。
- 团队、渠道能下钻到批次。
- 批次能下钻到历史记录。
- 筛选条件跨页面保留。
- 今日为 0 的业务人员可以确认完成，管理员/组长能看到其确认状态。

### 可访问性

- 侧边栏分组和当前入口具备清晰语义。
- 所有表头、筛选和抽屉有可读标签。
- 状态不只依赖颜色，同时提供文本或图标含义。
- 键盘可以完成筛选、排序、打开详情、关闭详情和跨页跳转。
- 打开详情后焦点进入详情，关闭后回到触发按钮。
