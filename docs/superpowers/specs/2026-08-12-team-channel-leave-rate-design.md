# 团队与渠道退群率设计

> **历史归档，停止执行。** 本文只用于追溯当时的设计或实施过程；涉及资源部确认、手填进群/注册/开单、岗位权限、统计日期或旧前端的内容均不是现行规则。当前口径请看 [当前业务规则](/Users/aaaa/Desktop/数据统计/docs/business/current-business-rules.md)。

## 目标

在“团队表现”和“渠道分析”的主表中直接展示退群率，让管理员和组长无需打开详情即可比较小组、人员和渠道的退群情况。

## 统计口径

- 退群率公式固定为：`退群数 ÷ 入群数`。
- 入群数为 0 时显示“分母为 0”，不显示 `0%`，避免误认为没有退群。
- 继续使用当前分析查询返回的成熟批次转化率口径，不新增第二套计算方式。
- 退群率以现有 `ConversionRates.leaveRate` 为唯一数据来源，不修改录入数据、日期筛选或权限。

## 页面变化

### 团队表现

- 小组表现表在“转化与效率”区域增加“退群率”。
- 人员表现表在“转化率”区域增加“退群率”。
- 两张表的“退群率”表头均可点击排序。

### 渠道分析

- 渠道质量表在“转化与效率”区域增加“退群率”。
- “退群率”表头可点击排序。
- 原有渠道详情抽屉继续显示退群率，不重复修改。

## 排序规则

- 默认排序保持当前规则不变。
- 点击“退群率”后按数值升序或降序排列。
- “分母为 0”的记录使用缺失值排序规则，排在有有效退群率的记录之后；样本是否可排名的现有优先级保持不变。

## 技术边界

- 只修改团队表格、渠道表格及相关组件测试。
- 不修改 `calculateConversionRates`，因为退群率计算已经正确存在。
- 不引入新依赖，不改变表格其他列、筛选条件或详情跳转。

## 验证标准

1. 小组、人员和渠道三种行都显示正确格式的退群率。
2. 入群为 0 时显示“分母为 0”。
3. 三处退群率表头均可排序，点击后行顺序正确。
4. 表头分组的列数与实际列数一致。
5. 聚焦测试、完整单元测试和生产构建通过。
