# 接粉与炒群兼任设计

## 目标

让同一位一线员工用一个账号同时处理接粉和炒群；进入系统后，侧栏同时显示“接粉工作台”和“群内客户”。客户仍分别记录接粉负责人、炒群负责人和专家负责人，不能混成一笔责任。

## 范围

本次只支持 `RECEPTION` 与 `GROUP_OPERATOR` 互相兼任。组长、专家、财务和管理岗位维持原规则，不借这次改动取得额外权限。

## 数据模型

保留 `User.role` 作为主岗位，保证现有报表和历史事件的口径不变；新增 `UserRoleAssignment` 作为兼任岗位表。每个用户最多有一条同岗位记录，迁移时会把现有主岗位补写成一条岗位记录。兼任岗位只能与主岗位同属一个小组。

## 权限与客户归属

- 接粉工作台要求拥有接粉岗位：只显示本人导入、本人负责的客户。
- 炒群工作台要求拥有炒群岗位：只显示 `groupOperatorOwnerId` 为本人，或由组长配置到本人名下的接粉员客户。
- 同一人兼任时，组长可把该员工配置为自己的接粉协作对象；这是合法的“自己接粉、自己炒群”。
- 接粉与炒群权限由当前访问的工作台动作决定，不能因为兼任而绕过客户归属或跨组查看。

## 界面

- 管理员和组长编辑一线成员时，主岗位保持单选；增加“兼任岗位”复选项，仅显示另一个一线岗位。
- 兼任账号左侧出现两个工作入口；同一链接只显示一次，公共入口（打卡、设备账号等）不会重复。
- 姓名旁可显示“接粉 / 炒群”标签，便于组长配置配合关系。

## 数据与统计

不复制客户、不复制订单，也不新增两套业绩。接粉指标仍从接粉负责人和接粉动作计算；炒群指标仍从炒群负责人、入群和推专家流程计算。`User.role` 继续保存历史主岗位，避免历史报表被这次兼任改坏。

## 安全与回滚

所有 API 均必须按实际拥有的岗位和客户归属二次校验，不能只靠侧栏隐藏入口。迁移只新增表并回填，不删除或改写用户、客户和业绩数据；移除兼任岗位仅删除对应分配记录。

## 验收

1. 接粉主岗兼任炒群后，能同时看到两个工作台。
2. 该账号只能在接粉页处理自己的客户，在炒群页处理自己被分配的客户。
3. 没有兼任的接粉员和炒群员行为不变。
4. 同一客户不会因兼任而被重复统计。
5. 跨组客户和无关客户仍返回 403 或不显示。
