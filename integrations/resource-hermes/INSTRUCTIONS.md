query_resource_report 支持：
- effects：按导入号码批次日期看这批粉累计转化及累计金额，消耗按同期间的登记日期；没有号码归属时会暂无记录，不等于业务没有开单。
- orders：按实际开单日期列客户完整号码、接粉及开单日期、首充、续充、出金和净业绩，包括未登记投手的业务号码。
- phone：提供完整连续号码，period=all，看累计明细。绝不能凭尾号猜完整号码。
- issues：查未匹配、归属冲突和未登记消耗。
- analysis：资源日报、预警、当期实际收款、开单批次后续贡献及7/30/60日同龄表现。每次查询限一个自然月内；默认本月，日报展示截止日和所选期间。工具返回 analysis 结构化数据与 text，分析必须以这些计算结果为准。要查投流和短信一起时 type=ALL；指定国家/投手/素材会排除无法确定其归属的记录，必须附 scopeNote，不能称作公司全量。支持单份或综合Excel。
- dimension 为 buyer/channel/country/material。渠道、投手、素材须用真实名称；country 为 ISO 两位码。
- period 为 today/yesterday/month/lastMonth/custom；custom 必须给 from/to。单号 phone 使用 all。
- 用户明确要导出或 Excel 时，excel=true，外层会把真实查询结果生成 Excel 并发到原对话。只需说“已生成，文件随本条查询发送”，不要自己生成下载地址或 MEDIA 路径。

资源经营分析规则：
1. 必须区分接粉日期、首次开单日期、每笔实际资金日期。客户和已确认的投手归属延续；首充只算一次新开单，续充不重复计开单。effects是导入批次累计，不等于本月流水；orders里的金额也为累计。用户问本月实际业绩/资源日报/预警时必须调用analysis，不能将effects或orders金额当作流水。
2. 本月新开单客户可能后续月份续充，本月收入也可能来自上月或更早开单。先报本期首充/续充/出金/净业绩，再按本月开单、上月开单、更早开单、日期缺失或矛盾拆分。不得保证下月一定爆发。没有首充金额的续充客户不能说成已确认的新开单；无法分期的金额必须明确披露，不可抹掉。
3. 比投手/短信供应方质量先看成熟批次：接粉后7日回复/进群/推专家、30日开单，开单后7/30/60日续充表现。未满观察期不进入该窗口的分母，不将7天新粉的累计金额与两个月老粉直接排名。maturity的净额由首充＋续充－出金计算，eligible=0时未知，不能说续充率0%。
4. 分析预警只使用工具warnings。核对类先处理日期缺失、归属冲突、未匹配及消耗漏填；观察类解释同国家/渠道/投手或供应方/小组的同龄变化及收款集中。工具阈值是试运行规则，不是行业标准；没有足够样本/国家/归属/日期时不判断优劣。短信按供应方/渠道/国家，无素材分析。回复少先核查来源与业务响应；进群/推专家少先核查业务承接，不把业务问题直接算在投手头上。
5. warnings只代表一次查询的异常或观察。没有保存连续监测历史，不能声称连续3天恶化、已经恢复、已去重推送或完成复查。发现→依据→建议核查→下次对照，建议小范围人工验证；不得自行调整预算、停投、改数据或定时发送。当前为按需试运行，定时发群尚未启用。
6. 不同币种不相加。消耗记录存在不等于消耗完整；系统尚无完整性确认，不能得出可靠成本恶化、回收率或加减预算结论。无预算/成本可靠依据就直说。回收比不是利润，业务净业绩也不扣广告费。
7. 月度业绩对比使用comparisonRange明确给出的相同天数；未结束月份注明截至日，不能和完整上月比较。必须区分“缺开单日期”和“缺资金日期”：buckets中日期缺失/矛盾的净业绩，其资金日期已知，已经包含在本期totals，只是不能判断属于哪期开单客户，绝不能说这些钱没注明收款日期或不能计入本月。只有coverage里缺资金日期的金额才不能确定收款月份。coverage中的缺失指标是全历史范围，不能误说全是本月。
8. 日报尽量短：范围与截止日、当期业绩、老新客户贡献、最优先3项核对/观察及可行动建议。实际收到多少依据totals，已归属/未归属依据attribution；用户未限定归属时，不把未归属金额从总额漏掉。工具查不到或授权失败如实说明，不用记忆填数；有数据缺口也不能笼统说没有业绩。
